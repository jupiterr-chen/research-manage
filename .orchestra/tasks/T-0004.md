# T-13 详情页展示 coverage.notices

- ID: T-0004
- 创建: 2026-09-22
- 分支: `fix/T-13-coverage-notices`(已从 develop 切出并处于当前工作区;不要建分支、不要 commit)

## 目标

reports-fetcher 新契约(integration-kit 2026-09-22 更新)把「报告期未知」等说明**聚合到 `results[].coverage.notices`**(至多一次),不再逐条放进 `results[].warnings`。
本系统的任务详情页与 API 需要把 `notices` 展示出来,否则用户在页面上看不到这些提示。

## 背景 / 现状

先读 `AGENTS.md` → `CLAUDE.md` → `integration-kit/API.md` §4(`coverage` 与 `notices` 语义;`period_source` 枚举含 `document`)→
`app/services/report_jobs.py::finalize_remote`(第 194 行起)→ `app/web/templates/fragments/report_job_detail.html`。

现状:
- `finalize_remote` 只把 `results[].warnings` 汇总进 `warnings_json`(前缀 `symbol: `),`coverage.notices` 没有进入任何本地字段;但完整 `results` 已原样存进 `results_json`,所以模板里 `r.coverage.notices` 是可取到的。
- 模板第 39 行只显示 `覆盖 selected/requested` 与「历史不足」chip。
- 更新后的 mock(`integration-kit/mock/server.py`)在 `success/partial/no_reports` 场景的 `coverage.notices` 形态见其 `_coverage()`;真实生产会给「共发现 N 个逻辑报告组,按 --last k 截断」「报告期未知…」等文本。

## 范围

允许改动:
- `app/services/report_jobs.py`(仅 `finalize_remote`:把每个 result 的 `coverage.notices` 也汇总进 `warnings` 列表,前缀同样为 `symbol: `,去重)
- `app/web/templates/fragments/report_job_detail.html`(证券结果段显示该证券的 notices)
- `tests/unit/test_reports_unit.py`(新增/修改用例)
- `docs/REPORTS-FETCHER.md`(§5 表「partial 保留可用文件」或新增一行说明 notices 的展示位置)

禁止改动:
- 其它文件;`integration-kit/**`;不重构;不部署、不 ssh

## 验收标准

- [ ] `finalize_remote`:`warnings` 汇总 = 各 result 的 `warnings` + `coverage.notices`(顺序:先 warnings 后 notices;同一 result 内去重;`coverage` 缺失/`notices` 非列表时不报错)。`report_ids`、`error_*` 逻辑不变。
- [ ] 模板:每个证券结果段在覆盖信息下方新增一行 `<p class="muted">提示:…</p>`(或 `<ul>`)列出 `r.coverage.notices`(为空不渲染);全部经自动转义,无 `|safe`。
- [ ] 单测:构造 `results=[{... "warnings": ["w1"], "coverage": {"notices": ["n1", "n1"]}}, {... "coverage": {}}]` 调 `finalize_remote`,断言 `warnings == ["SYM: w1", "SYM: n1"]`;再渲染详情页断言 `n1` 出现且 200;既有测试全部保持通过。
- [ ] `docs/REPORTS-FETCHER.md` §5 增一行「coverage.notices」:说明它会并入任务 `warnings` 并在证券结果段展示。
- [ ] 通过并贴真实输出:`./.venv/Scripts/pytest.exe tests/unit -q`;`./.venv/Scripts/pytest.exe -m reports_mock tests/integration/test_reports_mock.py -q`(mock 已在跑:`docker compose -f integration-kit/compose.yaml ps`);`./.venv/Scripts/ruff.exe check . && ./.venv/Scripts/ruff.exe format --check .`。
- [ ] `git status --short` 只出现允许改动清单内的文件。

## 实现提示

- `warnings` 列表用「已见集合」去重即可,不要改成 set 丢失顺序。
- 模板里用 `r.coverage.get("notices")` 而不是 `r.coverage["notices"]`(dict 缺键时 Jinja 的 `[]` 会退回 getattr,T-0002 踩过 `items` 的坑)。

## 已知坑

- 本机 `HTTP_PROXY` 劫持 127.0.0.1;客户端已忽略系统代理。
- 业务代码里不得出现 `X-Mock-Scenario` / `/__mock/` 字符串常量(有静态检查测试)。
